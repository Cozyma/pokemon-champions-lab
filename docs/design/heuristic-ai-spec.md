# ヒューリスティックAI 行動原則

poke-envの`SimpleHeuristicsPlayer`をベースに、`fast_battle.py`に内蔵している対戦AIの行動原則。

---

## 意思決定フロー

```
ターン開始
 │
 ├─ 強制交代中？ → 最適な交代先を選択
 │
 ├─ 技フィルタリング
 │   ├─ PP=0の技を除外
 │   ├─ disabled技を除外
 │   └─ ねこだまし: スイッチイン直後でなければ除外
 │
 ├─ メガシンカ判定（canMegaEvo時）
 │   └─ _should_mega_evolve → move N mega
 │
 ├─ 先制技でKOできる？ → 交代せず先制技
 │
 ├─ 交代すべきか判定（_should_switch_out）
 │   ├─ YES → 最適な交代先を選択
 │   └─ NO ↓
 │
 ├─ ステルスロック/まきびし等を撒けるか？
 │   └─ 相手残り3体以上 & **未設置** → 撒く
 │
 ├─ こちらにステロ等がある & 除去技がある？
 │   └─ こちら残り2体以上 → 除去する
 │
 ├─ 積み技を使うべきか？
 │   └─ HP満タン & 対面有利 & 合計ブースト+2以上の積み技 → 積む
 │
 └─ 最大ダメージ技を選択（スコアリング）
```

---

## 1. 技選択スコアリング

### 計算式

```
score = base_power × STAB × category_ratio × accuracy × expected_hits × type_effectiveness
```

| 要素 | 計算方法 |
|------|---------|
| **base_power** | 技の威力 |
| **STAB** | タイプ一致なら ×1.5、不一致なら ×1.0 |
| **category_ratio** | 物理技: 自分A実数値 / 相手B実数値、特殊技: 自分C / 相手D |
| **accuracy** | 命中率（0〜100） |
| **expected_hits** | 連続技の期待ヒット数（通常は1） |
| **type_effectiveness** | タイプ相性倍率（0, 0.25, 0.5, 1, 2, 4） |

### ステータス実数値の推定

```python
stat_estimation = ((2 × 種族値 + 31) + 5) × ランク補正
```

ランク補正: +1以上 → `(2 + rank) / 2`、0以下 → `2 / (2 - rank)`

### 現在の限界

- **持ち物補正を考慮しない**（こだわりハチマキ/メガネの1.5倍等）
- **特性による火力補正を考慮しない**（ちからもち、テクニシャン等）
- **追加効果を評価しない**（ひるみ率、やけど率等）
- **相手のHP残量を考慮しない**（確定数計算をしていない）

## 2. 交代判定（_should_switch_out）

### 条件: 以下のいずれかに該当 AND 有利な交代先が存在する場合

| 条件 | 理由 |
|------|------|
| 防御ランク ≤ -3 | 物理技で致命的なダメージを受ける |
| 特防ランク ≤ -3 | 特殊技で致命的なダメージを受ける |
| 攻撃ランク ≤ -3（物理AT） | 火力が出ない。物理ATは `A種族値 ≥ C種族値` で判定 |
| 特攻ランク ≤ -3（特殊AT） | 火力が出ない。特殊ATは `C種族値 ≥ A種族値` で判定 |
| 対面スコア < -2.0 | タイプ相性＋速度＋HP比率で大幅不利 |

### 「有利な交代先が存在する」の定義

控えの中に対面スコア > 0 のポケモンがいること。

### 現在の限界

- **相手の交代を読まない**（交代読み技変更がない）
- **先制技の存在を考慮しない**（タスキ＋先制技で倒せる場合も交代してしまう）
- **交代時の被弾ダメージを計算しない**（交代先が耐えられるか未検証）

---

## 3. 対面スコア（_estimate_matchup）

### 計算式

```
score = 攻撃相性 − 防御相性 + 速度ボーナス + HP比率ボーナス
```

| 要素 | 計算 | 値の範囲 |
|------|------|---------|
| **攻撃相性** | 自分のタイプが相手に与える最大倍率 | 0.25〜4.0 |
| **防御相性** | 相手のタイプが自分に与える最大倍率 | 0.25〜4.0 |
| **速度ボーナス** | 自分が速い: +0.1、遅い: -0.1 | ±0.1 |
| **HP比率ボーナス** | (自分HP% - 相手HP%) × 0.4 | -0.4〜+0.4 |

### 定数

```python
SPEED_TIER_COEFICIENT = 0.1    # 速度差のボーナス
HP_FRACTION_COEFICIENT = 0.4   # HP比率のボーナス
SWITCH_OUT_MATCHUP_THRESHOLD = -2.0  # これ以下なら交代検討
```

### 具体例

| 対面 | 攻撃相性 | 防御相性 | 速度 | スコア |
|------|---------|---------|------|--------|
| ガブリアス vs マリルリ | 1.0 (地→水等倍) | 2.0 (フェアリー→ドラゴン) | +0.1 | -0.9 |
| ガブリアス vs リザードン | 2.0 (地→炎/岩) | 1.0 (炎→ドラゴン等倍) | +0.1 | +1.1 |
| ハッサム vs ウルガモス | 0.25 (鋼→炎) | 4.0 (炎→鋼虫) | -0.1 | -3.85 → 交代 |

### 現在の限界

- **タイプ相性のみ**で技の実際の威力を見ない（C20の草技も考慮される）
- **STABのみ考慮**。サブウェポンの打点を評価しない
- **種族値の差を考慮しない**（同じタイプ相性ならA200とA50を同評価）

---

## 4. 交代先選択

### ロジック

```python
交代先 = 控えの中で対面スコアが最大のポケモン
```

### 現在の限界

- **交代時の被弾を計算しない**（交代ターンに相手の攻撃を受ける）
- **後続の対面まで考慮しない**（「ここで受けて次のターンで返す」等）
- **役割集中を避けない**（特定のポケモンに負荷が集中する）

---

## 5. ステルスロック / 設置技

### 使用条件

```
相手の残りポケモン ≥ 3 AND 相手側に未設置
```

対応する設置技:
- ステルスロック (stealthrock)
- まきびし (spikes)
- ねばねばネット (stickyweb)
- どくびし (toxicspikes)

### 除去技の使用条件

```
自分側にステロ等がある AND 自分の残りポケモン ≥ 2
```

除去技: こうそくスピン (rapidspin)、きりばらい (defog)

### 現在の限界

- **相手が設置技を持つか予測しない**
- **ステロダメージ量を計算しない**（炎/氷/飛行への4倍ステロの価値を定量化しない）
- **あくび等で流される展開を読まない**

---

## 6. 積み技の使用判定

### 使用条件

```
HP満タン AND 対面スコア > 0 AND 技のブースト合計 ≥ +2 AND 対象ステータスが+6未満
```

### 対象技の例

| 技 | ブースト合計 | 使用される？ |
|---|------------|------------|
| つるぎのまい | A+2 = 合計+2 | ✓ |
| りゅうのまい | A+1, S+1 = 合計+2 | ✓ |
| ちょうのまい | C+1, D+1, S+1 = 合計+3 | ✓ |
| てっぺき | B+2 = 合計+2 | ✓ |
| めいそう | C+1, D+1 = 合計+2 | ✓ |
| こうそくいどう | S+2 = 合計+2 | ✓ |
| のろい(非ゴースト) | A+1, B+1, S-1 = 合計+1 | ✗（合計+2未満） |

### 現在の限界

- **HP満タン限定**（オボン回復後やたべのこし回復後は対象外）
- **1回しか積まない**（対面有利なら2回積むべき場面がある）
- **積み技の恩恵を定量化しない**（確定数が変わるかどうかを見ない）
- **相手のアンコール/ちょうはつを読まない**

## 7. メガシンカ判定

基本方針: **メガシンカ可能なら行う**。以下の例外のみ見送る。

### 例外A: タイプ変化による不利（10体）

メガシンカでタイプが変わるポケモンについて、以下のいずれかが成立する場合はメガしない:
- 相手タイプからの被ダメ倍率がメガ後に増加する
- 自分の最高火力技のSTAB＋相性スコアがメガ後に低下する

対象: Charizard-X, Pinsir, Gyarados, Ampharos, Aggron, Altaria, Chimecho, Audino, Feraligatr, Meganium

### 例外B: メガ前特性が状況的に有効（2体）

| ポケモン | 特性 | メガしない条件 |
|---------|------|--------------|
| Clefable | Unaware (天然) | 相手に正のステータスブーストがある |
| Venusaur | Chlorophyll (葉緑素) | 天候が晴れ |

### 実装

- `MEGA_TYPE_CHANGES` 辞書（10体のタイプ変化テーブル）
- `MEGA_VALUABLE_ABILITIES` 辞書（2体の特性テーブル）
- `_should_mega_evolve()` で判定し、`_choose_action()` が `move N mega` を送信

### 拡張ポイント

`MEGA_VALUABLE_ABILITIES` にエントリを追加することで、他のポケモンの特性チェックも容易に追加可能。候補:
- Alakazam (Magic Guard) — 間接ダメージ圏内のとき
- Sableye (Prankster) — 変化技を先制で撃ちたいターン

## 8. ブラッシュアップ候補（未実装）

### 優先度高（効果大・実装容易）

| 改善点 | 内容 | 期待効果 |
|--------|------|---------|
| **ダメージ推定ベースの交代判定** | 相手STAB技の推定ダメージで確1/確2を計算。確1→即交代、確2&遅い→交代 | 致命的な居座りの回避 |
| **確定数ベースの積み判断** | 積んだら確1になるかを計算し、積む価値を定量化 | 無駄な積みの回避 |
| **先制技の考慮** | 交代判定で「先制技で倒せるなら交代しない」 | 過剰な交代の回避 |
| **交代先のHP残量考慮** | 交代先が被弾に耐えられるか事前計算 | 交代死の回避 |
| **持ち物補正の反映** | こだわりスカーフの速度、鉢巻/メガネの火力をスコアに反映 | 技選択精度向上 |

#### ダメージ推定ベースの交代判定（詳細仕様）

**利用可能な情報:**

| 情報 | 取得元 | 精度 |
|------|--------|------|
| 自分の実数値（A/B/C/D/S） | request JSON `side.pokemon[].stats` | 正確 |
| 自分のHP | request JSON `side.pokemon[].condition` | 正確 |
| 相手の種族名 | バトルログ `\|switch\|` | 正確 |
| 相手の種族値 | 種族名 → pokechampデータ or Showdown pokedex | 正確 |
| 相手のステータス推定 | `calc_stat(種族値, IV=31, EV=32, Lv=50)` | 近似（EV配分は仮定） |
| 相手のHP% | バトルログ `-damage` | 正確 |
| 相手の持ち物 | 発動するまで不明 | 不完全 |

**推定ダメージ計算:**
```
相手のSTABタイプ技（威力80仮定）で自分へのダメージを推定:
  opp_atk = calc_stat(opp_base_atk, 31, 32, 50, neutral)  # 仮定
  my_def  = 自分のdef実数値（request JSONから正確に取得）
  damage  = calc_damage_range(power=80, atk=opp_atk, def=my_def, stab=True, type_eff=相性)

  確1 = max(damage) >= my_hp  → 即交代
  確2 = max(damage) * 2 >= my_hp AND 相手が速い → 交代
  確3以上 → 居座りでOK
```

**持ち物不明の扱い:**
- 持ち物が判明するまでは「持ち物なし」で計算（控えめな推定）
- こだわりハチマキ/メガネの可能性は使用率データで確率的に加味（Phase 3.5以降）

#### バトルログから発見された具体的バグ（要修正）

2026-04-16のログ分析（screenshot-team vs mega-gengar-team）で判明:

| Turn | 問題 | 原因 | 修正内容 |
|------|------|------|---------|
| 1 | ねこだまし → ゴーストに無効 | **メガシンカ未選択**が根本原因。メガミミロップ(きもったま)なら当たる。`canMegaEvo:true`を無視している | ~~`_choose_action`で`canMegaEvo`時に`move X mega`を送信~~ **修正済み**（セクション7参照） |
| 2 | ねこだまし再使用（失敗） | ターン1限定の制約をAIが知らない | ~~ターン追跡 + fake-out使用済みフラグ~~ **修正済み**（スイッチインターン追跡で制御） |
| 15-19 | ステロ連打（設置済み） | 設置済みチェックがない | ~~ログから`\|-sidestart\|`を追跡~~ **修正済み**（相手側の`_parse_side_conditions`で設置済みチェック） |
| 16 | Struggle（PP切れ） | PP管理なし | ~~requestのpp残量を参照して0の技を回避~~ **修正済み**（`pp > 0`フィルタ追加） |

### 優先度中（効果大・実装中程度）

| 改善点 | 内容 |
|--------|------|
| **相手の型推定** | 使用率データから持ち物・技構成を推定 → 被ダメ計算精度向上 |
| **サブウェポン考慮** | STABだけでなく全技の打点を対面スコアに反映 |
| **ねこだまし優先使用** | 出した直後に確定先制+ひるみで1ターン得する |
| **HP管理** | 受けポケモンの回復技（はねやすめ等）のタイミング判断 |

## 9. Showdownデータ活用によるAI強化計画

Showdownの`data/`には技・特性・アイテム・ポケモンの**完全なデータ**がTypeScript形式で格納されている（56,612行 + Champions mod 21,432行）。現在のAIはこのデータをほぼ活用していない。

### 利用可能なデータ

| ファイル | 行数 | AIに有用な情報 |
|---------|------|--------------|
| `data/moves.ts` | 21,318 | basePower, type, category, priority, accuracy, flags(contact等), secondary(追加効果), onTry(ねこだまし制約等) |
| `data/abilities.ts` | 5,667 | onModifyAtk(ちからもち等), onStart(いかく), onDamagingHit(さめはだ) |
| `data/items.ts` | 8,167 | onModifyDef, onModifySpe, megaStone, isChoice |
| `data/pokedex.ts` | 20,976 | baseStats, types, abilities, weightkg |
| `data/typechart.ts` | 484 | 完全なタイプ相性テーブル |
| `data/mods/champions/moves.ts` | 1,133 | チャンピオンズ固有の技変更 |
| `data/mods/champions/abilities.ts` | 66 | チャンピオンズ固有の特性変更 |
| `data/mods/champions/items.ts` | 1,053 | チャンピオンズ固有のアイテム |

### 段階的な活用ステップ

#### Step 1: TSデータのJSON変換パイプライン（基盤）

Showdownの`.ts`ファイルをPythonから参照可能なJSONに変換するスクリプトを作成。

```
engines/showdown/data/moves.ts → data/showdown-cache/moves.json
engines/showdown/data/abilities.ts → data/showdown-cache/abilities.json
engines/showdown/data/items.ts → data/showdown-cache/items.json
engines/showdown/data/pokedex.ts → data/showdown-cache/pokedex.json
```

Showdownの`node build`で`.js`が生成されるので、それをNode.jsで`JSON.stringify`してもよい。

#### Step 2: 技データの参照によるスコアリング改善

現在のAIは技の`basePower`と`type`しか見ていない。moves.jsonから以下を参照：

| 参照フィールド | 活用方法 |
|--------------|---------|
| `priority` | 先制技の判定（現在は固定リストだがデータ参照に切替） |
| `flags.contact` | 接触技判定（さめはだ、ゴツメ回避の判断） |
| `secondary.chance` + `secondary.boosts` | 追加効果の評価（ひるみ30%等をスコアに加算） |
| `onTry` / `condition` | ねこだまし（ターン1限定）、ねむるの制約等 |
| `self.boosts` | りゅうせいぐんのC-2等、自己デバフを技スコアに反映 |
| `drain` | ドレイン技（ギガドレイン等）の回復量をスコアに加算 |
| `recoil` | 反動技のリスクをスコアから減算 |

#### Step 3: 特性データの参照による対面評価改善

abilities.jsonから相手の特性効果を推定し、技選択と交代判定に反映：

| 参照フィールド | 活用方法 |
|--------------|---------|
| `onModifyAtk` / `onModifySpA` | 相手のちからもち等の火力倍率を被ダメ推定に反映 |
| `onDamagingHit` | さめはだ等の接触反動を技選択時に回避判断 |
| `onStart` | いかくの攻撃低下を交代時の評価に反映 |
| `onSourceModifyDamage` | マルチスケイル等の被ダメ軽減を確定数計算に反映 |
| `immunities` | ふゆう(地面無効)等をタイプ相性に上乗せ |

#### Step 4: アイテムデータの参照

items.jsonから持ち物効果を推定：

| 参照フィールド | 活用方法 |
|--------------|---------|
| `isChoice` | こだわり系（技固定）を検出 → 相手が同じ技を連打してきたら読み交代 |
| `megaStone` | メガシンカ可能判定（`canMegaEvo`の裏付け） |
| `onModifySpe` | スカーフのS1.5倍を速度比較に反映 |
| `fling.basePower` | なげつけるの威力推定 |

#### Step 5: 統合 — request JSON + Showdownデータ で精密判断

request JSONから得られる情報とShowdownデータを組み合わせ：

```python
# request JSONから:
opponent_species = "Garchomp"  # ログから取得
my_stats = {"atk": 182, "def": 115, ...}  # request JSONから正確に取得
available_moves = [{"id": "earthquake", "pp": 8}, ...]  # request JSONから

# Showdownデータから:
move_data = moves_json["earthquake"]  # basePower=100, type=Ground, flags={...}
opp_data = pokedex_json["garchomp"]  # baseStats, types, abilities
opp_ability_data = abilities_json[opp_data["abilities"]["0"]]  # 特性効果

# 統合判断:
damage = calc_damage(my_stats, move_data, opp_data)  # 精密ダメージ計算
is_contact = move_data["flags"].get("contact")  # さめはだ回避判断
opp_can_ohko = estimate_incoming(opp_data, opp_ability_data, my_stats)  # 交代判定
```

### 見積もり

| Step | 実装量 | 優先度 |
|------|--------|--------|
| Step 1 (JSON変換) | 小（スクリプト1つ） | **最優先** — 他の全Stepの前提 |
| Step 2 (技データ) | 中 | 高 — スコアリング精度が大幅に向上 |
| Step 3 (特性データ) | 中 | 高 — 交代判定精度が向上 |
| Step 4 (アイテム) | 小 | 中 — こだわり系の読みが可能に |
| Step 5 (統合) | 大 | RL Phase 0の前に完了したい |

---

### 優先度低（RLで解決すべき）

| 改善点 | 理由 |
|--------|------|
| 交代読み | 相手の行動予測が必要。ヒューリスティックでは限界 |
| ダブル交代 | 両者の交代を同時に考慮。ゲームツリー探索が必要 |
| 複数ターン先の展開予測 | 「ここで耐えて次で倒す」等。価値関数の学習が必要 |
