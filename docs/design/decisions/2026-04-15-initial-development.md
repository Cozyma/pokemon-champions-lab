# 初期開発経緯（フェーズ2 → 2.5）

## 背景

ポケモンチャンピオンズ（2026年4月8日ローンチ）の構築考察・対面シミュレーションツールとして本リポジトリを新規作成。対戦パーティ同士の有利不利を統計的に判定する機構を目指した。

## 設計判断の流れ

### 1. アプローチ選定

3つの候補（モノリシック / データ分離 / Notebook中心）から**モノリシック構成**を採用。
個人CLI用途でリポジトリクローン共有が前提のため、シンプルさを優先。

### 2. シミュレーションの段階設計

| フェーズ | 内容 | 判断 |
|---------|------|------|
| 1 | タイプ相性ベース静的判定 | スキップ（物足りない） |
| **2** | 貪欲AI対面シミュ（交代なし） | **採用**。コスパ最良 |
| 3 | 交代あり3v3フルシミュ | 将来 |

フェーズ2の途中で展開評価（積み技バリエーション）もスコープに含めた。

### 3. チャンピオンズ固有仕様への対応

開発中にユーザーからチャンピオンズの固有仕様が段階的に提供され、随時反映した：

- **個体値廃止** → IVsは常に31固定
- **努力値変更** → 各0〜32、合計66、EV1=実数値1（本編の`floor(ev/4)`ではない）
- **アイテムプール** → こだわりハチマキ/メガネ/いのちのたま等が未実装。スカーフのみ
- **メガシンカ復活** → 59形態。構築のメインギミック
- **技・特性の調整** → アイアンヘッドひるみ率低下、まひ確率変更等

これにより当初の「本編準拠」設計から「チャンピオンズ準拠」に全面移行。

### 4. フェーズ2.5の追加

フェーズ2完了後、対面シミュの精度に以下の課題が判明：

- 命中率が100%扱い（きあいだま70%が必中）
- 急所なし
- 先制技の戦略的使用が考慮されない
- 天候がない（晴れパ・雨パが評価不能）
- 積み技の使用判断がCLI手動指定のみ

これらを「フェーズ2.5」として対面精度の底上げを実施。

### 5. 先制技AIの設計

ユーザーからの要望を反映した判断ロジック：

```
相手より遅い場合の技選択:
1. 先制技で倒せる → 先制技
2. 先制技で倒せない＆相手の攻撃で確定死:
   a. 先制技の急所(×1.5)で倒せる → 先制技（ワンチャン）
   b. 急所でも無理 → 最大ダメージ技（削り）
3. 相手の攻撃を耐える → 最大ダメージ技
```

「どうせ落ちるなら急所ワンチャン」は実戦的な判断として重要。

## 技術スタック

| 選定 | 理由 |
|------|------|
| Python 3.10+ | シミュレーション・統計処理に最適。フェーズ3のAI実装も見据える |
| Pydantic v2 | データモデルのバリデーション。YAML↔Python変換が自然 |

| モンテカルロ(N=1000) | アイテム・特性の状態管理が複雑なため全列挙を廃止し一本化 |

## 現在のシーケンス評価の制限事項（フェーズ3で解決予定）

現在の3v3シーケンス評価は「1v1を最後まで戦い切ってから次の対面に移る」構造。
これにより以下の制限がある：

| 問題 | 影響 |
|------|------|
| 1v1途中の交代不可 | りゅうせいぐんC-2後の撤退、不利対面の早期交代ができない |
| 相手の交代がない | 防御側が常に居座る。有利対面維持の交代が未評価 |
| 相手の技読み未対応 | 交代先に有効打を撃つプレイングを考慮しない |
| 天候の動的切り替わり | 交代で天候要員が出ても天候が変わらない。メガシンカ後の天候特性（メガリザY→ひでり等）も未反映 |
| ステロダメージなし | 交代時のステルスロックダメージが未実装 |
| 天候5ターン終了なし | 特性天候が永続扱い。長期戦で影響 |

→ **全て「ターン単位のシーケンス進行」への構造変更で解決可能**。
フェーズ3の中核課題として計画する。
