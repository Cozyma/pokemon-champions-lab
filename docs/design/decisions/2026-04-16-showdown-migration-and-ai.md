# Showdown移行・RL環境構築・AI改善（2026-04-16）

## 背景

前日（4/15）にpokechampの自前バトルエンジンをフェーズ2.5まで完成させた。93テスト、42特性、天候・命中率・急所・先制技AI・積み技自動評価・3v3シーケンス評価・自己デバフ技を実装済み。

しかし以下の構造的限界が明確になった：

- battle.pyが1317行に肥大化（リファクタリングが必要）
- 技の詳細処理（900+技の追加効果）が未実装で精度に限界
- 学習環境としてのバトルエンジンをゼロから作るのは車輪の再発明

## 判断の流れ

### 1. battle.pyの分割リファクタリング

1317行のbattle.pyを4ファイルに分割：
- `abilities.py` (260行): 特性テーブル + 判定関数
- `ai.py` (136行): _choose_move + 技選択ヒューリスティクス
- `calc.py` (164行): _calc_all_moves + 天候補正
- `battle.py` (757行): BattlePokemon + simulate_1v1

さらにモンテカルロループ内の重複コードを`_FighterState`/`_apply_attack`/`_apply_damage_modifiers`/`_end_of_turn`に抽出。

### 2. Pokemon Showdownの発見と統合

ユーザーから「対戦シミュの内部化による学習環境構築が最終目標」との方針が示され、Pokemon Showdownを調査。

**重大な発見**: Showdown本家に**チャンピオンズ対応が既にマージ済み**（PR #11910, 2026-04-11）。`data/mods/champions/`に21,432行のmod（EV式変更、新メガ、技変更、PP変更すべて）が実装されていた。

**判断**: 自前エンジンでの技効果実装は断念。Showdownをバトルエンジンとして採用し、pokechampは分析レイヤーとして残す。

```
役割分担:
  Showdown = バトルエンジン（完全な技効果・状態異常・交代）
  pokechamp = 分析ツール（構築評価・マッチアップ・パーティビルダー）
```

### 3. フォーク・サブモジュール化

- Cozyma/pokemon-showdown-championsとしてGitHubフォーク
- `engines/showdown/`にgit submoduleとして取り込み
- MITライセンス表記を`THIRD_PARTY_LICENSES.md`に追加

### 4. poke-env接続テスト

poke-env 0.15.0をインストールし、ローカルShowdownサーバーに接続。
- フォーマット名: `gen9championsbssregma`
- 6体チーム必須、Item Clause（同じアイテム禁止）
- メガストーン名の正式名を確認（Lopunnite, Dragoninite等）
- RandomPlayer同士の対戦成功（20ターン、メガシンカ動作確認）

### 5. Gymnasium RL環境構築

`src/pokechamp/env.py`にChampionsEnvを作成：
- 観測空間: 76次元Box（自分/相手ポケモン状態、技、チームHP、天候、行動マスク）
- 行動空間: Discrete(9)（技4択 + 交代5択）
- 報酬: 勝利+1.0/敗北-1.0、気絶±0.3、HP差分±0.1
- ライブテスト成功（27ターンでエピソード完了）

### 6. RLロードマップ策定

参考文献（ReBeL記事、沈(2022)修士論文）から7フェーズのロードマップを策定：

| Phase | 内容 |
|-------|------|
| 0 | リプレイ模倣学習 + 使用率データ基盤 |
| 1 | PPO強化 |
| 2 | Self-Play |
| 3 | 選出AI |
| 3.5 | 使用率ベース不完全情報補完 |
| 4 | 信念状態（ベイズ推定） |
| 5 | CFR / ReBeL |

沈(2022)の2段階学習（リプレイ模倣→Self-Play、72hでElo 1543）を参考にPhase 0を追加。チャンピオンズ公式使用率データの連携も計画。

### 7. パーティビルダー

`pokechamp build`コマンドを実装。タイプ相性ベースの高速フィルタで：
- 現チームの弱点脅威TOP10を表示
- カバーできる追加候補TOP10を提案
- 210体プール全スキャンで数百ms

### 8. Showdown精密評価（--evaluate）

パーティビルダーのTOP候補をShowdownで実戦評価する機能を追加。

**速度問題と解決**:
1. poke-env + WebSocket: ~15秒/戦 → 遅すぎて実用的でない
2. Showdownサブプロセス直接実行: ~1秒/戦 → **15倍高速化**

`fast_battle.py`にSimpleHeuristicsPlayerのロジックを内蔵し、stdin/stdoutでShowdownと直接対話。サーバー不要。

### 9. チーム形式のShowdown移行

pokechamp独自のteam.yaml形式からShowdownペースト形式(.txt)に全面移行：
- 7チーム全てをtxt化
- `showdown_loader.py`でペーストパーサーを作成
- `team_converter.py`を削除
- poke-envにそのまま渡せるようになった

### 10. ヒューリスティックAI改善

SimpleHeuristicsPlayerの行動原則をドキュメント化し、3つの改善を実装：

| 改善 | Before | After |
|------|--------|-------|
| 交代判定 | タイプ相性スコアのみ | ダメージ推定で確1/確2判定 |
| 先制技 | 考慮なし | KO可能なら交代せず先制技 |
| 交代先選択 | 相性スコア最大のみ | 被弾でOHKOされる候補を除外 |

### 11. バトルログ分析で発見されたAIバグ

実戦ログから5つのバグを発見：

| 問題 | 根本原因 |
|------|---------|
| メガシンカしない | `canMegaEvo`を無視（**最重要**） |
| ねこだまし連打 | ターン1限定の制約をAIが知らない |
| ステロ連打 | 設置済みチェックがない |
| PP切れでStruggle | PP=0チェックなし |
| タイプ無効技を選ぶ | 相性計算が不完全 |

全て「Showdownエンジンは完璧に処理するが、AIが情報を読んでいない」系の問題。

### 12. Showdownデータ活用計画

Showdownの`data/`（56,612行+Champions mod 21,432行）をAIが参照する5ステップの計画を策定：

1. TS→JSON変換パイプライン（基盤）
2. 技データ参照（追加効果、反動、ドレイン）
3. 特性データ参照（火力倍率、免疫、接触反動）
4. アイテム参照（こだわり検出、メガ判定）
5. 統合（request JSON + 全データで精密判断）

## 技術的な教訓

### 自前エンジン vs 既存エンジンの判断

pokechampの自前エンジンは構築評価ツールとしては有用だったが、学習環境としてのバトルエンジンをゼロから作るのは非効率。Showdownに**チャンピオンズ対応が既にマージされていた**ことが決定打。

自前で積み上げたチャンピオンズ知識（champions-rules.md, pool-m-a-1.md）は、Showdown改造の仕様書として無駄にならなかった。

### エンジン精度とAI精度の分離

Showdownエンジンは技効果・状態異常を完璧に処理する。しかし**AIが情報を活用できなければ意味がない**。バトルログ分析で「エンジンは正しいがAIが間違う」パターンが多数発見された。

### 速度の重要性

poke-env経由（15秒/戦）からサブプロセス直接（1秒/戦）への切り替えで実用性が劇的に改善。パーティビルダーの`--evaluate`が実用的な速度になった。
