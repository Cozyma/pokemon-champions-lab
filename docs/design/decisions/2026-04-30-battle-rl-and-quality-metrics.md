# バトルRL再訓練・品質指標・報酬設計（2026-04-30）

## 背景

4/28-30のヒューリスティクス改善(49%→71%)と観測空間再設計(101→278dim)を経て、RL訓練を再開。
選出RLは77%に到達したが、バトルRLは57%で頭打ち。勝率だけでは原因が見えないため、品質指標と報酬設計を追加。

4/28の186dimから段階的に拡張:

| 変更 | 内容 | dim |
|------|------|-----|
| 4/28 | 初期設計(タイプ+ステ+判明技+相手チーム+ブースト+天候+設置技) | 186 |
| 4/30 | 自控え2体の全情報(タイプ+全ステ+HP+技相性) | +55 → 241 |

| 4/30 | 行動順推測(直近3ターン速度順+速度勝率) | +5 → **278** |

設計思想: **人間が見ている情報と同等の情報をRLに渡す**。

### 頭打ちの原因分析

勝率だけでは「何が悪いのか」が見えない。そこで品質指標を導入。

---

## 4. 品質指標(battle_metrics.py)

勝率以外の3指標を定義:

### 4-1. 無駄行動(wasted_moves)

**定義**: 相手が交代していないのに免疫技を撃った回数。
相手が交代した結果として免疫になったケースは除外(読み外れは仕方ない)。

```
格闘技 → ゴーストタイプ(相手が居座り) = 無駄 ← カウント
格闘技 → ゴースト(相手が交代で出てきた) = 読み外れ ← カウントしない
```

### 4-2. 積み成否(setup_kos / setup_wasted)

**定義**:
- **setup_kos**: ブーストを持った状態でKOを取った回数(投資回収成功)
- **setup_wasted**: ブーストを持った状態で自分が倒された回数(投資未回収)
- **setup_success_rate**: setup_kos / setup_attempts

### 4-3. 交代ROI(switch_gained / switch_lost)

**定義**:
- **switch_gained**: 交代後に抜群技を当てた(有利対面を作れた)
- **switch_lost**: 交代先が2ターン以内に倒された(悪い交代)
- **switch_roi**: (gained - lost) / total_switches

### ヒューリスティクスAIの測定結果(15戦サンプル)

```
Wasted moves: 1/109 (0.9%)
Setup: 3 KOs / 4 attempts (75% success), 1 wasted
Switches: 66 total, +0 gained, -17 lost (ROI: -0.26)
```

**交代ROIが-0.26 = 交代するたびに不利になっている。** 技選択は問題ないが交代判断が弱い。

---

## 5. 品質ベース中間報酬

勝ち+1/負け-1だけでは「なぜ負けたか」の学習信号が弱い。
品質指標を報酬に変換:

| 報酬 | 値 | トリガー |
|------|-----|---------|
| 免疫技ペナルティ | **-0.3** | 相手が交代していないのに免疫技を撃った |
| 積み+KOボーナス | **+0.2/KO** | ブースト状態でKOを取った |
| 無駄積みペナルティ | **-0.2/ターン** | ブースト状態で自分が倒された(積みターン数に比例) |
| 悪交代ペナルティ | **-0.2** | 交代先が2ターン以内に倒された |

既存の中間報酬(HP変化+0.1、KO+0.3)に加算。

### 報酬設計の意図

- **免疫ペナルティ**: タイプ相性の基礎を強制学習
- **積みボーナス/ペナルティ**: 「積むなら回収する」行動回数理論の内在化
- **悪交代ペナルティ**: 交代先の安全性を考慮させる
