# 選出RL実装・Self-Play設計・ヒューリスティクス追加改善（2026-04-23）

## 背景

前日(4/22)に技選択RLが83%(Gen9)に到達。7チーム中6チームに10/10勝利。
唯一の全敗マッチアップ mega-venusaur-charizardx(0/10)の分析から、2つの問題が判明:

1. **Body Pressの火力が防御ブーストを反映していない** — Corviknight +6 Iron DefenseでもU-turnの方がスコアが高い
2. **選出がヒューリスティクス固定** — Volcarona(炎→草/毒4x抜群)がVenusaur相手に選出されない

また「ヒューリスティクス改善→RL再訓練」の手動サイクルがスケールしないため、選出RLとSelf-Playへの移行を決定。

## 1. ヒューリスティクス追加改善

### Body Press防御ステータス参照

`_score_move`でBody Press(格闘, 80bp)が通常の物理技と同じ`atk/opp_def`比率で評価されていた。
Body Pressは防御ステータスで攻撃する特殊技のため、`def/opp_def`比率に補正し、さらに防御ブーストを反映。

**Before**: +6 def Corv vs Venusaur: Body Press=27.9, U-turn=48.9 → U-turn選択
**After**: +0 def: BP=42, UT=49(UT) / +2: BP=84(BP) / +6: BP=168(BP)

### 無駄交代抑止

低スコア交代判定(`best_score < 40`)で交代先のmatchupが現在より+0.5以上改善する場合のみ交代。
**Before**: Azumarill↔Aegislash無限ループ(59ターン)
**After**: 有効打なしと判断して居座り、試合進行

### 効果

| マッチアップ | 修正前 | 修正後 |
|-------------|--------|--------|
| vs mega-venusaur-charizardx (heuristic) | 0/10 | **7/20 (35%)** |
| vs mega-venusaur-charizardx (Gen10 RL) | 0/10 | **5/10** |

## 4. 選出RLアーキテクチャ

### 設計判断: 2モデル分離

SB3のMaskablePPOは固定obs/action空間を要求するため、選出と技選択を別モデルにする。

```
SelectionAgent: obs=team_preview(216dim) → action=Discrete(20)  [C(6,3)]
BattleAgent:    obs=battle_state(101dim)  → action=Discrete(9)   [4技+5交代]
```

### 代替案と却下理由

| 案 | 却下理由 |
|----|---------|
| 単一拡張モデル(Approach B) | SB3が可変obs/action空間を非対応。パディングは容量の無駄 |
| 階層モデル(Approach C) | SB3にネストenv非対応。カスタム訓練ループの実装コスト大 |

### 選出エピソード = 1ステップ文脈バンディット

```
reset() → team preview obs(216dim: 自6体types + 相手6体types)
step(action) → 3体選出 → バトル全実行 → reward(+1/-1)
```

- 行動空間: `Discrete(20)` — C(6,3)のルックアップテーブル
- 報酬: 勝利+1, 敗北-1（即時、gamma=1.0）
- PPO設定: n_steps=512, batch_size=128, n_epochs=10, ent_coef=0.05

### ヒューリスティクス追加改善: 無意味な積み抑止

対戦ログ分析で発見: Corviknight が Aegislash(鋼/ゴースト)相手にBody Press(格闘→ゴースト**免疫**)なのに
Iron Defenseを3回積む → 攻撃できないまま相手に+6つるぎのまいを許す。

**原因**: 積み判定が「回復量 > 被ダメ → 壁として成立 → 積め」と判断するが、自分の攻撃が0ダメージかを確認していない。

**修正**: 積み判定に「best_atk_score > 0（相手にダメージを与えられるか）」チェックを追加。

**効果**: vs mega-scizor ヒューリスティクス同士 0/10 → 6/10。
ただしGen11のバトルRLは修正前のAIで訓練されており、自力でscizor 6/10に到達 — RLが自己学習で同等の解を見つけた。

## 7. 技術的知見

### 選出と技選択の分布不整合問題

旧バトルRLをそのまま新しい選出RLと組み合わせると性能が低下する。
- 旧バトルRL: ヒューリスティクス選出(Garchomp/Corv/Primarina中心)で訓練
- 選出RL: Volcarona/Lopunny等、これまで選出されなかったポケモンを選ぶ
- → バトルRLが未経験のポケモンを操作できない（特にミラーマッチ）

**解決策**: バトルRLをゼロから選出RL込みで訓練（Gen11方式）。
Phase 3の交互訓練(微調整)よりGen11(スクラッチ)が優れた結果。

### 手動改善 vs RL自己学習

Gen11はscizor 10/10を**ヒューリスティクス修正なし**で達成（24kステップ）。
積み中攻撃力チェックの修正はAI相手に効果的だが、RLは同等の解を自力で学習した。
ヒューリスティクス改善の役割は「RLの学習補助」から「Self-Playの対戦相手品質」にシフト。

## 8. Self-Play実装と開始

### 実装

SelectionEnvにp2のRLモデル対応を追加:
- `p2_selection_model`: p2の選出RL
- `p2_battle_model`: p2のバトルRL
- `_play_battle`でp1/p2それぞれのモデルを使い分け

`scripts/train_selfplay.py`:
- 毎ラウンド: 選出訓練(vs過去の自分) → バトル訓練(選出固定) → 評価 → スナップショット
- 対戦相手プール: `models/selfplay_pool/`に毎ラウンドのモデルを蓄積
- 対戦相手選択: 50%最新版、50%ランダム（多様性確保）
- 評価: vsヒューリスティクス(退行チェック) + vs過去の自分(成長チェック)

### 開始

Gen11の100%(70/70)達成を受けてSelf-Play Phase 4を開始。
初期方策: selection_best(90%) + ppo_masked_best(Gen11 24k=100%)。
10ラウンド、2000steps/ラウンド。

## 9. Self-Play初期結果と方針転換

### Self-Play Round 1結果

| 指標 | 結果 |
|------|------|
| vs ヒューリスティクス | 86%（screenshot 0/10以外全勝） |
| vs 過去の自分(v0) | 95% |

Self-Play中のミラーマッチ最適化により、ヒューリスティクス固有パターンへの対応が退行（policy forgetting）。
ヒューリスティクス混合訓練(50% Self-Play + 50% ヒューリスティクス)に修正したがvsヒューリスティクス60%に低下。

### 根本原因: 対戦相手AIの品質問題

Self-Playの性能は「対戦相手の初期品質」に依存する。ヒューリスティクスAIが最適行動をしていないため:
1. **選出RLが弱い相手に勝てる選出を学んでしまう** — 汎化しない
2. **Self-Playの初期方策が弱い** → 自分と戦っても学習信号が弱い

### 方針転換: リプレイベース定石化 → 観測空間見直し → Self-Play

**Phase 5: リプレイ分析と定石化**
1,136件のリプレイ + team-building-analysisから:
- 対面別の最適行動を抽出（T1行動、確定行動マトリクス）
- 選出率×勝率のデータ駆動な選出判断
- ヒューリスティクスAIの行動品質を引き上げ

**Phase 6: 観測空間の再設計**
現状の問題:
- 選出obs(216dim): タイプ情報のみ。ステータス・特性・技構成が欠落 → 同タイプの異種族を区別不能
- バトルobs(101dim): 相手の技情報がない → 対面判断の情報不足
- リプレイ分析で「何の情報が判断に必要か」を特定してからobs設計

**Phase 7: 強化された対戦相手でSelf-Play再開**

### 戦略タグフレーム（案）

```
構築戦略タグ:
  設置型:    SR/Spikes持ち → 序盤は設置優先、退場OK
  積みエース型: 竜舞/蝶舞/剣舞 → 起点作り後に展開
```
