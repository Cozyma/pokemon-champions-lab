# ヒューリスティクスバグ修正・行動回数理論の積み判定への適用（2026-04-28）

## 背景

対戦相手プールを32チームに拡大した結果、ヒューリスティクスAIのベースライン勝率が49%と判明。
不利マッチアップのログ分析から複数のバグと構造的問題を発見。

---

## 1. バグ修正

### 1-1. 選出: STABタイプではなく実際の技タイプで評価

**問題**: `_select_team_preview`がポケモンのタイプ(STAB)で攻撃力を評価。Corviknight(鋼/飛行)はBody Press(格闘)しか攻撃技がないのに、鋼/飛行の攻撃力で評価 → ゴースト相手に格闘免疫が無視される。

**修正**: 各ポケモンの実際の技タイプをShowdownデータから取得し、技タイプの最大相性で評価。

**効果**: mega-gengar 0/10→10/10, shioinu 0/10→10/10, rb-neko 0/10→6/10

### 1-2. タイプルックアップ: pokedex.jsonフォールバック

**問題**: `_get_species_types`がlegacy YAMLローダーのみ使用。Aegislash、Archaludon等がYAMLに存在せず空リスト → 格闘→ゴースト免疫が認識されない。

**修正**: YAMLで見つからない場合`data/showdown-cache/pokedex.json`にフォールバック。

### 1-3. ピボット技を積み判定の攻撃手段から除外

**問題**: 積み判定の「攻撃手段ありチェック」がU-turn(0.25x微ダメ)を有効な攻撃と判定 → Body Pressがゴースト免疫でもU-turnのスコア>0で積みを許可 → 無意味なIron Defense。

**修正**: 積み判定のbest_atk計算でピボット技(U-turn/Volt Switch/Flip Turn)を除外。逃げる前提なら積む意味がない。

**効果**: gray 0/5→4/10, mana 0/5→6/10

---

## 2. 構造的問題: 積み判定の分岐爆発

### 問題

バグ修正を重ねた結果、積み判定が100行超の条件分岐に:
- 物理/特殊チェック(2パス)
- 壁+回復判定
- HP閾値判定
- ピボット除外
- slugfest判定(別の物理/特殊チェック)

**各修正が別のマッチアップを退行させる**。1つ直すと別が壊れるモグラ叩き状態。

根本原因: 「積むべきか」を条件分岐の組み合わせで判断しているため、分岐同士の相互作用が予測不能。

### 行動回数理論での解決

[行動回数の収支理論](2026-04-24-action-theory.md)を積み判定に直接適用:

```
各行動を「行動回数の収支」で比較:
- 攻撃: 現在の火力でKOまでのターン数
- 積み: 1ターン消費 → 火力UP/被ダメDOWN → 以降のターン効率改善
- 回復: 1ターン消費 → 生存ターン増加
- 交代: 1ターン消費 → 有利対面で行動回数を稼ぐ
```

**実装**: 100行超の分岐を以下の統一ロジックに置換:

```python
# 各積み技について:
1. 積み後のattack_score を_score_move(simulated_boosts)で計算
2. 積み後のincoming_damageを_estimate_incoming_after_boost()で計算
3. 行動回数を比較:
   - action_turns = HP / (incoming - recovery)  # 何ターン生存するか
   - ko_turns = opponent_HP / attack_score      # 何ターンでKOするか
4. gainを判定:
   - 積みで「KO不可→KO可」になるなら大きな正のgain → 積む
   - 両方KO可だが1ターン以上速くなるなら積む
   - 積みで生存ターンが足りなくなるなら負のgain → 積まない
```

### ヘルパー関数

| 関数 | 目的 |
|------|------|
| `_estimate_incoming_after_boost()` | 防御ブースト後の被ダメ推定。def→物理のみ軽減、spd→特殊のみ軽減 |
| `_count_action_turns()` | HP/(被ダメ-回復量)で生存ターン数を計算 |
| `_turns_to_ko()` | 攻撃スコアから相手KOまでのターン数を推定 |

### 自然に解消されるエッジケース

| ケース | 旧(分岐) | 新(行動回数) |
|--------|---------|-------------|
| ゴースト相手にBody Press | 専用チェック必要 | atk_after=0 → 自動スキップ |
| 特殊相手にIron Defense | 物理/特殊分岐必要 | incoming_after=incoming_now → gain≤0 → スキップ |
| ピボットのみの攻撃手段 | 除外リスト必要 | ピボット除外済みのスコアで自動判定 |
| 回復で永遠に耐えられる | 壁判定分岐 | action_turns=∞ → can_ko判定に統一 |

## 3. 結果

| 指標 | 修正前 | バグ修正後 | 行動回数理論 |
|------|--------|-----------|-------------|
| ベースライン勝率 | 49% | 62% | **63%** |
| 0/5マッチアップ数 | 5 | 7 | 4-6 (乱数依存) |
| 積み判定のコード行数 | ~110行 | ~120行 | ~70行 |
| 分岐の深さ | 4-5段 | 5-6段 | **2段** |

---

## 4. 残課題

- 一部マッチアップ(daisangen-r2500, teramatsu-r2100)は構築相性で不利
- `_estimate_opponent_max_damage`が80bp STAB前提で、110bp技(Thunder等)を過小評価
- 選出判定はまだタイプ相性ベースで、素早さ・積み適性を考慮していない → RLに任せる範囲
